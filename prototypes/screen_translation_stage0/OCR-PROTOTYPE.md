# Локальный OCR и mock, 30.10.2026

Это следующий ограниченный этап стенда в том же Runner. Реального провайдера, сети, endpoint и платных запросов нет. Непройденные эксплуатационные проверки этапа 0 не объявляются завершёнными. Установка — команда Profile из README; публичные Release/default Profile не включают новый capture/OCR UI.

## Поток и владение

`CaptureSource` получает source sample на своей serial video queue, применяет существующий лимит до 4 выборок/с и передаёт изображение в `ScreenOCRPipeline` только при явном выборе режима «Локальный OCR без записи». Pipeline читает `SCStreamFrameInfo.videoOrientation` (EXIF), создаёт fingerprint 96×160 и ждёт стабильности 0,4 с. Исходный статус-бар исключён из распознавания и сравнения. При отсутствии orientation metadata результат сбрасывается с ошибкой, ориентация не угадывается.

Один последовательный worker выполняет `VNRecognizeTextRequest`: accurate, zh-Hans/en-US, без автоматической языковой коррекции. Он удерживает один активный кадр; ещё один последний кадр может ожидать, прежний pending заменяется. Смена изображения/размеров/ориентации инвалидирует ревизию, отменяет старый request и очищает прежний UI. Timeout 3 с отменяет request и инвалидирует его поздний результат; при ошибке нужен явный stop/start. Рендер готового результата планируется отдельно от входящих capture callbacks, поэтому не требует следующего видеокадра.

Vision получает orientation в image handler; bbox результата уже относится к ориентированному изображению. Применяется только Y flip из нижнего левого в верхний левый угол, без повторного вращения. Все bbox нормализованы и ограничены 0…1. Чистая функция EXIF-преобразований служит тестируемой границей для будущих raw-box источников, а не повторным преобразованием ответа Vision.

ID блока сохраняется в пределах результата данного frame; UUID сессии + монотонный frameId защищают публикацию. События доставляются через latest-only mailbox. Commit состояния UI и проверка ревизии атомарны; этот внутренний callback не вызывает renderer/stop обратно. PiP renderer запускается после callback отдельной ограниченной Main-задачей.

## Вывод и данные

В режиме OCR PiP всегда использует проверенную защиту `preventsCapture=true`. Source видит чёрную область вместо PiP-текста; закрытая приложением область не восстанавливается. OCR и QA-видеозапись одновременно запрещены. Распознанные строки и изображения хранятся в памяти и освобождаются при остановке; в diagnostics только состояния, ID, числа блоков/символов, длительности и mockApplied, без строк/изображений.

Пользователь изменил целевой вывод: нужна визуальная копия интерфейса, а не список строк. `ScreenFramePainter` копирует локальный кадр, заменяет распознанные китайские надписи в их областях и сохраняет остальной интерфейс. Для теста используются известные фразы; AI не подключён. Непереведённые области сохраняют исходный текст. Это растровая реконструкция, не доступ к дереву элементов чужого приложения и не изменение его UI.

Новые требования: полный текст без многоточий, одна страница, допустимы изменение компоновки и общепринятые сокращения. Текстовые области растут, соседние OCR-блоки и следующие горизонтальные области интерфейса сдвигаются; расширенная компоновка целиком вписывается в фиксированную портретную страницу 720×1280. Ориентация исходника учитывается отдельно: результат PiP остаётся портретным. Изображение обрабатывается локально; для будущего AI отправляются только строки и ID.

Полнота строк проверяется через видимый UTF-16 range CoreText; если полное размещение не удалось, выводится ошибка раскладки вместо частичного текста. Плотный экран может уменьшить общий масштаб: сохранение всего текста не доказывает комфортной читаемости в системном PiP. Целевые экраны и ограничения реального размера окна требуют отдельного теста.

Mock переводит только известные синтетические фразы с confidence ≥0,8; в визуальном макете возможна явно обозначенная частичная замена. Только для fixtures допускаются различия пробелов и формы двоеточия. Вне словаря изображение остаётся исходным. Для будущего AI: краткий интерфейсный стиль, общепринятые «кол-во», «шт.», «нерж. сталь» допустимы; числа, валюты/единицы, артикулы, бренды и отрицания не теряются и не конвертируются. Важные свойства ради экономии места не удаляются.

Максимум 50 observations / 6000 символов; превышение — `ocr_limit`, а не молчаливое усечение. `ocrDurationMs` и время отрисовки измеряются раздельно; это ещё не полная задержка до физически отображённого PiP.

Portable core tests прошли: 8 EXIF orientations, Vision flip/clamp, нормализация без потери чисел/отрицаний, детерминированные горизонтальные строки, fingerprint/stability/reset/clock, late-frame и session/revision gates. Mock tests: точные fixtures, OCR-пробелы/двоеточие, сохранение ID/порядка/bbox/чисел, отказ неизвестному/изменённому/низкой confidence, отсутствие частичного fallback. Native iOS15-target typecheck SDK27.1 с warnings-as-errors прошёл; без opt-in флагов тоже прошёл. Старый garage translation 3/3 прошёл.

Физически пользователь подтвердил китайский OCR в PiP на встроенной карточке. Content-free snapshot `ocr-first-observation.json`: 4 блока, 25 символов, один OCR duration 165,97 мс, PiP active, preventsCapture=true, QA off. Это не замер полного screen-to-PiP latency, P50/P95, OCR accuracy или скорости DeepSeek.

## Ограничения

- Grayscale detector использует среднюю разницу и локальное превышение в отдельных samples; тест обнаруживает один изменённый sample, который не виден по global mean. Изменение между точками уменьшенной сетки всё ещё можно пропустить. Это стартовая реализация: подавление баннеров и небольшие локальные изменения требуют корпуса и настройки порога; бесконечная анимация может мешать stability.
- Horizontal reading rows не реконструируют таблицы, вертикальное письмо или полноценные группы характеристик. Низкую confidence модель не «исправляет».
- Чистые unit tests не заменяют fault injection реального Vision request и проверку очереди Instruments.
- Нет сети, LRU, серверной авторизации, endpoint, retry UI текущего кадра, паузы, реального переводчика и облачного качества/стоимости.
- 15 минут, memory pressure/interruption/host termination, целевые Taobao/1688 и другие iPhone/iOS остаются в матрице непроверенных сценариев.

Публичные API сверены с локальными заголовками SDK27.1 и страницами Apple: [Vision text recognition](https://developer.apple.com/documentation/vision/vnrecognizetextrequest), [videoOrientation](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo/videoorientation). Документация не считается доказательством результата на устройстве.
