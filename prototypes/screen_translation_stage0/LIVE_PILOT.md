# Реальный перевод экрана: первая интеграция

Работа ведётся в основной копии `2a-user`, ветка `feature/screen-translation-stage0-20261030`; backend — в разрешённой пользователем текущей `feat/warehouse-isolation-20261001`. Commit, push, deploy и облачных вызовов в этой поставке нет. Это подготовка закрытого пилота, не подтверждение production-приёмки.

## Что соединено

Профиль Flutter → «Перевод экрана» → нативный экран согласия → системный ScreenCaptureKit picker → видеобуферы → стабильность/локальный Vision OCR → отдельный авторизованный endpoint 2A → DeepSeek через Yandex Responses → валидация → копия интерфейса в вертикальном sample-buffer PiP. Обычный `/api/translate` не меняется этим модулем.

Новый режим требует iOS 27. Во время нахождения в 2A реальные OCR/сетевые задачи приостановлены; после запуска PiP нужно перейти в переводимое приложение. Это исключает отправку текста собственного профиля и подробного перевода из 2A. При возврате работа отменяется. Выход из аккаунта, смена пользователя и закрытие экрана очищают нативные credentials. Ответ 401 останавливает захват и инвалидирует сохранённый токен; повторный запуск требует нового открытия из авторизованного Flutter-профиля.

Один OCR и один сетевой запрос; только последний pending-кадр. Отмена проверяется атомарно перед регистрацией HTTP; поздние ответы не публикуются. Исходные кадры и переводы хранятся только в ограниченной памяти сессии. Нет аудио, облачных изображений, QA-записи или mock fallback в реальном режиме. Диагностика содержит только состояния, размеры, длительности, счётчики и память; не текст/токен/payload.

PiP содержит одну страницу 720×1280. Русский текст переносится, области расширяются и следующие элементы сдвигаются; итог масштабируется на страницу без многоточий. Общепринятые сокращения разрешены промптом. Полная сохранность вывода проверяется CoreText. На очень плотном экране общий масштаб может сделать шрифт мелким: читаемость требует проверки на устройстве. Фон восстановлен простыми областями; идеальная реконструкция графики не заявлена.

Защита display layer предотвращает рекурсивное распознавание собственного перевода, но оставляет закрытую область в захвате. Данные под системным PiP не восстанавливаются. Пользователь сравнил это с PiP Translate и принял текущую границу; лучше перемещать окно с важных надписей. Изменения небольших областей обрабатываются регионально с сохранением остальных блоков; системные баннеры всё ещё могут менять доступную исходную картинку.

## Флаги и сборка

По умолчанию Dart `SCREEN_TRANSLATION_ENABLED=false` и нативный `SCREEN_TRANSLATION_LIVE` отсутствует. Карточка не создаёт auth/API/channel, захвата и новых запросов нет. Обычный plist не менялся ради этих capabilities.

Из корня `2a-user`, с уже подготовленным Flutter/Pods окружением:

```bash
python3 prototypes/screen_translation_stage0/build_live_pilot.py
```

Скрипт сохраняет имеющиеся Dart defines, добавляет только opt-in, использует Profile, существующую Apple team/certificate и отдельный `ScreenTranslationLive-Info.plist` с согласованными screen-capture/audio modes. Не использует provisioning updates, не создаёт ключей/профилей, не устанавливает приложение. Не совмещать тест с воспроизведением другого media в Runner; playback lease не воспроизводит звук и восстанавливает прежние category/mode/options.

Endpoint строится из текущего API base URL приложения, а bearer берётся из существующей авторизации. Для реальной работы этот же сервер должен содержать новый route и явную конфигурацию пилота. Backend-конфигурация: `2a-logistic-backend/docs/SCREEN_TRANSLATION_PILOT_CONFIG.example.env`, контракт: `docs/SCREEN_TRANSLATION.md` в backend. Секреты остаются на сервере. Пилот ограничен одним Node process/replica; нельзя выдавать локальные лимиты за общий распределённый бюджет.

## Проверки 30 октября 2026

- Profile Runner с live bridge и Flutter opt-in: сборка на SDK 27.1 / Xcode 27.1, существующее signing окружение.
- Сервер: 18 mock-only тестов; strict typecheck новых модулей, полный repository typecheck с heap 8 GiB, ESLint новых файлов. Auth scan имеет отдельное прежнее нарушение scanner/intake; новый endpoint распознан как authenticated.
- Flutter: 22 теста нового режима вместе со старым garage translate; отдельный web-only тест должен запускаться с Chrome. Тесты платформы/default-off/auth races и безопасных сообщений. Targeted analyze чистый.
- Native: HTTP URLProtocol контракт, память/TTL/LRU/версии, timeout/429/cancel/stop и отказ до старта HTTP; bbox/EXIF/стабильность; реальные пиксели sampler; CoreText full-text layout и сохранность соседних нетекстовых элементов. Это синтетические локальные тесты.
- Независимый read-only review проверил порядок блокировок foreground cancellation, завершение OCR deadline до HTTP и teardown при 401; блокирующих замечаний не осталось.

Физические прежние проверки и их видео описаны в README/ADR: iPhone 17 Pro Max, iOS 27.0.1. Они подтверждают capture/PiP/OCR прототип, но не новый HTTP flow. Итоговая live-сборка ещё не установлена и полный сценарий ещё не проверен. Пятнадцатиминутный прогон пользователь отменил; утечки, батарея, нагрев, memory pressure, host termination и длинная серия экранов не считаются принятыми.

## Следующий фактический gate

Нужны отдельная команда на публикацию backend и согласованный бюджет облачного теста. Существующие ключи нужного каталога подтверждены read-only; доступ ключа к выбранной модели ещё не проверен. Новые IAM-права/ключи автоматически не создаются. До живого вызова нельзя утверждать качество, стоимость, P50/P95 либо достижение 1–2 секунд. Финальная ручная проверка выполняется после подключения сервера: Taobao/1688, смена экрана, поворот/PiP, сеть/авторизация, остановка. Пользователя до этого этапа повторно не просить выполнять промежуточные тесты.

Откат локального пилота: собрать обычное приложение без opt-in и выключить только `SCREEN_TRANSLATE_ENABLED` на backend, завершив активную сессию. Старый перевод сохраняется; миграций нет.

## Навигация по полному снимку — 31 октября 2026

В текущем закрытом пилоте весь стабильный снимок распознаётся и переводится одним ограниченным запросом; нарезка выполняется после локальной отрисовки. Для 720×1280 формируются четыре перекрывающиеся полосы 16:9 по 405 px, включая середину. Графика не раздвигается; длинный перевод подбирает шрифт внутри исходной области и проверенного свободного места.

PiP получает конечную последовательность sample buffers по 15 секунд на участок (0, 15, 30, 45 секунд). Системные назад/вперёд переходят к началу соседнего участка, пауза фиксирует кадр и отменяет OCR/HTTP. Возобновление разрешает обработку актуального экрана. Перемотка готового снимка не вызывает ИИ. В конце последовательности просмотр приостанавливается; воспроизведение можно запустить заново. Закрытие PiP завершает сессию.

Не более восьми кадров-участков хранятся только в памяти; stop очищает таймер, буферы и очередь. Замена снимка защищена поколением очереди, устаревшие результаты pipeline не применяются. Физический синтетический тест подтвердил вперёд/назад/паузу поверх Калькулятора. Полный live-сценарий проверяется отдельно. Backend остаётся на опубликованном 66fb1cb; для навигации новых настроек Яндекса или серверного релиза не требуется.

Этот файл содержит хронологию. Ранние разделы про неопубликованный backend, отсутствие миграций и старые SHA описывают предыдущие этапы, а не текущее состояние. Платформы разделены: текущий переводчик — **iOS 27+**, Android-переводчик ещё не реализован. На Android и Web карточка и нативные вызовы скрыты даже при включённом Dart-флаге. Прежний OCR фотографий Android — отдельная функция, его отключать не нужно. Приложение продолжает поддерживать iOS15+, но запуск перевода на iOS ниже27 возвращает понятное сообщение о версии.

Воспроизводимая development-signed **Release** сборка iOS с переводчиком:

```sh
python3 tools/build_ios_translator_candidate.py
```

Команда включает Dart opt-in, `SCREEN_TRANSLATION_LIVE` и `SCREEN_TRANSLATION_PIP_MEDIA`, использует Live plist и существующее development signing. `DEBUG` и `SCREEN_TRANSLATION_STAGE0` не включаются; диагностический presenter и его тестовый интерфейс исключены. Default-сборки без opt-in сохраняют функцию выключенной. Это локальная Release-конфигурация, не App Store archive и не публикация.

Проверка Android без отсутствующего переводчика:

```sh
flutter build apk --release --flavor direct --no-pub --dart-define=SCREEN_TRANSLATION_ENABLED=false
```

Физическая проверка Android не выполнена при отсутствии подключённого Android. Распространение релиза, App Store/TestFlight, production-wide включение флага и изменение signing-доступа требуют отдельной команды. Наличие успешной Release-сборки не подменяет проверку фоновой работы на устройстве, нагрузочный прогон и оценку качества на согласованном корпусе.

В iOS translator Release candidate обе частоты Sentry Replay принудительно равны0 до инициализации SDK. Отправка ошибок не отключается. Маскирование custom native preview отдельно не доказано, поэтому opt-in сборка не полагается на него. Android Replay этим скриптом не меняется.

## Стандартная iOS-сборка после prerelease-подготовки

Актуальное состояние: обычные iOS Debug/Release/Profile и Xcode Archive включают live-переводчик через `ios/Flutter/ScreenTranslation.xcconfig`. Ранние указания этого документа о default-off относятся к историческому pilot-этапу. Открывать `ios/Runner.xcworkspace` → Runner → Product → Archive; pilot-скрипт больше не нужен для включения функции. Release использует только LIVE/PIP_MEDIA, без STAGE0/DEBUG; Android и Web остаются выключенными.

Для явного отключения задать `SCREEN_TRANSLATION_MODE=OFF` в Xcode Build Settings или xcodebuild. Это переключает plist, native flags и один feature define, сохраняя остальные defines. Replay выключен в обоих режимах. Инструкция и непроверенные публикационные пункты: [`ios/APP_STORE_REVIEW.md`](../../ios/APP_STORE_REVIEW.md). Эта настройка не означает публикацию или прохождение App Review.
