# Проверка экскурсии: самовыкуп

Проверены настоящие `SelfBuyoutScreen`, инструкция Alipay, форма создания и окно существующей заявки вместе с `TrainingTourHost` и проектным `GoRouter`. Данные в тестах фиктивные; запросы к API заменены сервисом-фикстурой. Обработчик создания заявки в фикстуре считает обращения и завершает тест ошибкой при попытке отправки.

## Исправленные причины

- Инструкция регистрировала `selfbuyout.instruction.continue`, пока кнопка продолжения была отключена. Экскурсия выбирала эту подсказку раньше вопроса об опыте. Теперь готовый якорь существует только после ответа; до ответа кнопка получает `.continue.waiting`. Пользователь отвечает самостоятельно. Реальный вопрос — было ли минимум три пополнения Alipay.
- Отключённая кнопка создания при отсутствии курса имела тот же якорь, что доступное действие. Теперь используется `selfbuyout.create.unavailable`. При отдыхе операторов отдельный якорь `selfbuyout.operators.unavailable` указывает на существующее сообщение.
- После просмотра формы список заявок оставался закрыт модальным окном. В форме, инструкции и деталях добавлен `selfbuyout.sheet.dismiss` на существующую ручку шириной 42 px. Экскурсия может объяснить ручное закрытие окна перед переходом к списку.
- Кнопка создания переполнялась по горизонтали на мобильной ширине 390 px, в том числе при первоначальном состоянии загрузки. Текст ограничен через `Flexible`; подписи, размеры и обработчики сохранены.
- `selfbuyout.request.status` привязан к строке текущего статуса в шапке деталей. Остальные экземпляры общей шапки сохраняют прежнее поведение.
- Повторная проверка обнаружила уведомление `GoRouterDelegate` во время построения общего хоста. Исправление отложенного обновления находится в общем `TrainingTourHost` и проверено повторным запуском этого интеграционного сценария.

## Проверенный путь

Тест начинает со второго шага темы: открытия формы суммы. Поиск пункта меню — отдельная проверка общей навигации. В теме семь шагов, в этом тестовом маршруте последовательно выполняются шесть шагов формы и заявки.

| Этап | Реальное действие и проверка |
| --- | --- |
| Открытие | Нажатие существующей кнопки «Создать заявку»; появляется инструкция первого обмена |
| Опыт Alipay | Отдельные прогоны «Да» и «Нет»; готовая кнопка продолжения появляется после ответа |
| Сумма | Открывается «Новая заявка»; найдено настоящее поле RMB и введено 100 |
| Реквизиты | Через кнопку QR открывается выбор источника: фото или файлы; системная команда Back возвращает к форме |
| Условия | Нажат настоящий переключатель согласия; переход через кнопку экскурсии |
| Отправка | Проверен точный якорь существующей кнопки отправки; сама кнопка не нажимается |
| Возврат | Ручка модального окна закрывает форму жестом; становится доступен номер существующей заявки |
| Детали | Нажат номер заявки; открываются детали с действием продолжения оплаты; экскурсия показывает текущий статус |
| Недоступность | Отдельные случаи отсутствия курса и отдыха операторов: готового действия создания нет |

После обеих веток опыта количество вызовов создания заявки равно нулю. Переходы выполняются через настоящую кнопку «Далее» экскурсии. При необходимости тест прокручивает содержимое окна экскурсии к этой кнопке: его содержимое допускает вертикальную прокрутку.

- `test/features/training/training_self_buyout_flow_test.dart`: четыре интеграционных сценария прошли на семишаговой теме после исправления хоста.

Повторный прогон четырёх сценариев прошёл; оба финальных снимка 390×844 просмотрены инструментом: поле суммы видно в настоящей форме, текст текущего статуса читается, рамка выделяет его строку и не закрывает буквы.

## Границы проверки

Нативный выбор конкретного файла/фото, настоящая отправка заявки, банковский QR, перевод юаней, проверка личности и работа на физическом устройстве здесь не выполнялись. Тесты подтверждают отображение и ручную проходимость учебного маршрута с локальными данными, а не выполнение финансовых операций или доступность сервиса для конкретного production-аккаунта.
