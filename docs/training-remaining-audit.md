## Фактические локальные проверки этого среза

- Свежий комбинированный запуск `training_remaining_transitions_test.dart` и `training_invoice_tariff_targets_test.dart`: **8/8 widget-тестов прошли** (лог `/tmp/training-invoice-notification-final.log`).
- Четыре теста remaining: настоящий калькулятор с mock API и последовательностью вес → объём → сумма; корневая WarehouseAddressCheckerSheet и возврат; настоящий SP каталог → child route → три вкладки → pop; настоящая NotificationsSheet → drag существующей ручки → восстановленная цель под модалкой.
- Четыре теста invoice/tariff: QR/manager варианты доступной оплаты (2); paid-first список → открытие оплаченного счёта → drag ручки → номер подходящего неоплаченного счёта → доступная оплата; точный текст тарифа (1). Кнопки платежа не нажимались.
- Ранее в этом срезе комбинация прежних 6 тестов и `garage_presentation_test.dart` завершилась **22/22 pass** (`/tmp/training-remaining-final-tests.log`). Это отдельный прогон до добавления двух новых сценариев, а не 22 новых проверки.
- Целевой `dart analyze` четырёх изменённых presentation-файлов (calculator/garage/invoices/notifications) и двух test-файлов: **No issues found** (`/tmp/training-remaining-final-analyze.log`). Полный analyze приложения в этом срезе не запускался.
- В harness существующая 9-секундная delayed-задача AnimatedHeroGlowBackdrop требует advance clock после teardown; у context.push фактический GoRouterState ребёнка отличается от routeInformationProvider URI. Тест проверяет GoRouterState настоящей детали. Host отдельно изменён родителем; тест экранов не доказывает весь coach.
- Дополнительный целевой регрессионный прогон калькулятора после добавления photos/insurance alias: **1/1 pass** (`/tmp/training-calculator-invalid-final.log`). Проверена последовательность результат → фото 2 при всего 1 → нет результата → фото 0 → результат → включение страховки с пустой суммой → нет результата → сумма 1500 → результат. Ранее приведённый анализ выполнен до этих последних двух пассивных обёрток; финальный общий анализ выполняет родитель.
- Дополнительный invoice sleeping regression: **1/1 pass** (`/tmp/training-invoice-sleeping-final.log`): открыта настоящая карточка счёта, кнопки `invoice.pay` нет, `invoice.pay.unavailable` точно совпадает с существующим PaymentOperatorSleepingNotice. Проверен только этот новый branch; полный набор параллельно проверяет родитель.
- Полного пользовательского 29-шагового прохождения с coach, системного выбора скриншота/OCR, реальной оплаты, отправки сообщений или создания рабочих черновиков в этом срезе не выполнялось.

## Рекомендации для интеграции

1. Основная кнопка бланка создаёт запись сразу: объяснить это до нажатия и не использовать создание как обязательную подготовку экскурсии.
2. Подготовка payments:1 теперь использует точный номер подходящего счёта и закрытие текущей модалки. При отдыхе операторов кнопки оплаты недоступны даже у неоплаченного счёта; добавлен точный `invoice.pay.unavailable` на штатное сообщение для блокирующей подготовки.
3. Между уведомлениями и адресом на одном `/` добавлена и проверена подготовка закрытия ручкой. Ручной уход во вложенную карточку участника СП остаётся отдельной границей (source-only).
4. Учитывать реальную вершину router stack, а не только routeInformationProvider: у проверенного context.push последний продолжал сообщать `/sp-finance`, когда на экране уже была `/sp-finance/purchases/11`.
5. Для tariffs:2 выбирать первый фактически отсутствующий параметр; для произвольного редактирования фото/страховки добавлены соответствующие missing-цели и regression проверки восстановления результата. Отсутствующая упаковка/тариф — отсутствие данных, не требование создать запись.
6. Скриншотный шаг описывает выбор изображения; OCR-результат и ограничения iPhone/Android нужно объяснять отдельно. Новости и правила открывают штатные дочерние маршруты.

Дополнительно просмотрен photos.open (за пределами этих 29 строк): цель находится на существующей первой фотокарточке, открывающей PhotoViewerScreen через root Navigator.push; требуется загруженное фото. Runtime-проверки просмотра фото в этом срезе нет.
